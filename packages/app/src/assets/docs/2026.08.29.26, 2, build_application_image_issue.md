`%5C` is a Windows backslash (`\`) that got URL-encoded. Thumbnail URLs were being written as `./assets%5Cfile.jpeg` instead of `./assets/file.jpeg`, so the browser looked for a file that does not exist.

**Cause.** `vite-plugin-image-presets` 0.3.5 (the Vite 8 update) switched from `pathe` to `node:path.join`. On Windows that produces `assets\file.jpeg`, then `encodeURI()` turns `\` into `%5C`. Older versions always used `/`, which is why this did not happen before.

**Fix.** A small Vite transform in `packages/app/vite.config.ts` rewrites those encoded backslashes in `?preset=` modules:

```20:31:packages/app/vite.config.ts
/** vite-plugin-image-presets 0.3.5 uses node:path.join, so Windows builds encode `\` as %5C in src/srcset. */
function fixWindowsImagePresetUrls(): Plugin {
    return {
        name: "fix-windows-image-preset-urls",
        transform(code, id) {
            if (!id.includes("preset=") || !code.includes("%5C")) {
                return;
            }
            return code.replaceAll("%5C", "/");
        },
    };
}
```
